# Contributing to Lazy LMS

Thank you for your interest in contributing to **Lazy LMS**! Lazy LMS is an open-source, modern, self-hosted Learning Management System built purely with standard PHP 8.2+, SQLite (PDO), Vanilla CSS, and Vanilla JavaScript with no heavy external frameworks.

---

## 🧭 Code of Conduct

We are committed to providing a friendly, safe, and welcoming environment for all contributors, regardless of experience level, background, or identity. Please treat fellow community members with respect and courtesy.

---

## 🛠️ Development Philosophy & Stack

1. **Framework-Free Simplicity**:
   - Keep the architecture lightweight, transparent, and modular.
   - Core stack: **PHP 8.2+**, **SQLite3 / PDO_SQLite**, **HTML5**, **Vanilla CSS**, **Vanilla JavaScript**.
   - No unnecessary Composer dependencies unless genuinely required (e.g., standard QR code generators or RFC-compliant 2FA).
2. **Strict Server-Side Security**:
   - Zero-trust model: never rely on client-side JS validation alone.
   - All public URLs must use 5–8 character alphanumeric IDs generated by `HashId`. Never expose raw numeric database auto-increment IDs.
   - Validate batch/course/lesson/attempt permissions server-side on every request.
   - All student uploads must reside outside the webroot at `storage/uploads/submissions/` and be downloaded through `/submissions/download/{id}`.
3. **UI / UX Standards**:
   - Modern, responsive layouts (tested across mobile 320px, tablet 768px, desktop 1280px+).
   - Use Boxicons (`bx` / `bxs`) for iconography.
   - Minimalist, clean design with dark mode support and glassmorphism accents.
   - Every file must include a reference comment: `Lazy LMS`.

## 🚀 Setting Up Your Local Environment

### Prerequisites

* PHP 8.2 or later
* PHP Extensions enabled in `php.ini`:
  - `pdo_sqlite`
  - `sqlite3`
  - `mbstring`
  - `openssl`
  - `fileinfo`
  - `curl`

### Installation Steps

1. **Fork and Clone the Repository**:
   ```bash
   git clone https://github.com/your-username/lazy-lms.git
   cd lazy-lms
   ```

2. **Configure Environment**:
   ```bash
   cp .env.example .env
   ```

3. **Install Dependencies (if any)**:
   ```bash
   composer install --no-dev
   ```

4. **Run Database Migrations & Seeders**:
   ```bash
   php database/migrate.php
   ```

5. **Start Built-in Development Server**:
   ```bash
   php -S 127.0.0.1:8080 -t public
   ```
   Open your browser to `http://127.0.0.1:8080/login`.

## 🌿 Git & Pull Request Workflow

1. **Create a Feature Branch**:
   ```bash
   git checkout -b feature/my-new-feature
   ```
2. **Write Clean, Documented Code**:
   - Follow PSR-12 coding guidelines for PHP.
   - Keep views modular in `app/Views/`.
   - Add database schema changes as versioned migrations in `database/migrations/`.
3. **Commit with Clear Messages**:
   ```bash
   git commit -m "feat(exams): add auto-save timer and descriptive answer uploads"
   ```
4. **Push to Your Fork**:
   ```bash
   git push origin feature/my-new-feature
   ```
5. **Open a Pull Request**:
   - Provide a concise description of changes.
   - Reference any relevant GitHub issues.
   - Verify test suite results in your PR description.
